# Implementation Plan: Workspace & Repository Setup (Phase 0)

This document outlines the step-by-step implementation plan for **Phase 0: Workspace & Repository Setup**, based on the technical specification defined in [`specs/0.0_WORKSPACE_AND_REPOSITORY_SETUP.md`](file:///home/jiggra/bite-backend/specs/0.0_WORKSPACE_AND_REPOSITORY_SETUP.md).

---

## 1. Goal Description

Establish a secure, clean, and production-ready workspace baseline for **Project Bite** (Photo-first AI Calorie & Macronutrient Tracker). 

The primary objectives are:
- Configure `.gitignore` to prevent secret leaks (`.env`), virtual environment binaries (`.venv/`), and build artifacts from entering source control.
- Create `.env.example` as a safe, unpopulated environment template for team reference.
- Initialize local `.env` with developer placeholders for Supabase PostgreSQL, Gemini API, USDA API, and Supabase JWT secrets.
- Pin baseline Python dependencies in `requirements.txt` (`FastAPI`, `LangGraph`, `asyncpg`, `pydantic-settings`, `httpx`, `pytest`).
- Maintain clean Git status tracking on the `main` branch and update progress in `PROJECT_PLAN.md`.

## 4. Proposed Changes

### Core Repository Configuration

#### [NEW] `.gitignore`
Establish rules to exclude sensitive data, Python artifacts, environments, and IDE files.

```gitignore
# Byte-compiled / optimized / DLL files
__pycache__/
*.py[cod]
*$py.class

# Environments
.venv/
env/
venv/

# Environment Variables & Secrets
.env
.env.*
!.env.example
*.pem
*.key

# IDE & OS Metadata
.vscode/
.idea/
.DS_Store
```

---

### Environment Variable Management

#### [NEW] `.env.example`
Provide an unpopulated, checked-in template for environment configuration.

```env
# PostgreSQL (Supabase Direct URL with Connection Pooling)
SUPABASE_POSTGRES_DIRECT_URL=postgresql://postgres.xxx:password@aws-0-region.pooler.supabase.com:6543/postgres

# Multimodal LLM & AI API Keys
GEMINI_API_KEY=your_gemini_api_key_here
OPENAI_API_KEY=your_openai_api_key_here

# USDA FoodData Central API Key
USDA_API_KEY=your_usda_api_key_here

# Supabase Auth / JWT Verification
SUPABASE_JWT_SECRET=your_supabase_jwt_secret_here

# Application Configuration
APP_ENV=development
LOG_LEVEL=INFO
```
